## 1. What changed and what now works

Working **locally** (Workers runtime via wrangler/miniflare), not deployed:

- **M0** — architecture, data model, Catherine tool boundaries, verified cost
  sheet with estimates separated, decisions list (`docs/`).
- **M1** — customers sign in by emailed link and submit requests with private
  attachments; Jack sees them from a separate session; notes and history
  persist across sign-out; customers cannot see each other's jobs or files;
  partners never get files; operator tools reject other roles; stale edits are
  refused instead of overwriting.
- **M2** — versioned quotes; the customer approves the exact version (content
  hash); Jack accepts only if the window fits his declared availability;
  dispatch only when both exist, with one structured work order per version;
  rejected or changed quotes never dispatch; email outbox with retry,
  give-up, manual retry, and "Unacknowledged" items in the queue.
- **M3** — Catherine runtime with a clearly labeled PROVISIONAL spec (not the
  approved one), recorded spec version/hash, provider, model, tokens and cost;
  five proposal-only tools that execute once, only after Jack approves (he can
  edit text first); model failures retried then shown, never touching the job;
  invalid or unknown tool calls rejected; monthly budget enforced in the app.
  OpenAI and Anthropic adapters exist but **no real model has been called**.
- **M4** — evidence and receipts, expense ceiling enforced, completion creates
  a numbered DRAFT invoice, issue/void-and-redraft revisions, manual payment
  confirmation, separate partner ledger. The brief's first test job gives
  $45.00 + $6.50 = **$51.50** (tax $0, labeled not configured) and a **$9.00**
  TEST partner share; replaying the completion event creates no second invoice.
- **M5 prep** — a browser run of the whole first test job across four separate
  accounts at an Android phone size, failed-notification recovery, access
  checks, and a backup → restore → access-check drill, all local.

Fix found while preparing M5: sign-in rate limiting would not have applied in
production (wrong client-IP header); corrected and tested.
